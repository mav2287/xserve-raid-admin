## Blocking: missing bindings that should be fixed

1. **The transport gate record is never tied to the pinned JAR (`PIN`).**
   - The `transport` command has no `--candidate-sha256`.
   - `check_transport.py` writes the JAR hash only inside `observations[*].jar_sha256`, alongside the original JAR's hash.
   - Lines 73–74 check the pin only when a top-level key happens to exist. Line 79 requires `PIN` in observations only for `factory` and `shared`.
   - As a result, `build/model-clean-transport.json` can pass without ever naming `PIN`.
   - **Fix:** add `transport` to line 79. Better, make pin presence mandatory for all 16 gate records (top-level `candidate_sha256`/`jar_sha256`, or an observation for the listed exceptions), instead of checking only when a key is present.

2. **The unit runner's own source is never proven.**
   - `audit/model-unit-runner.py` is not in its record's `sources` (only `tools/**.py` and `tests/**.py`). It is recorded only as a bare `runner_sha256`.
   - **Fix:** require `unit['runner_sha256']==sha(ROOT/'audit/model-unit-runner.py')`, and require that this equals the hash of `git show CORE:audit/model-unit-runner.py`.

3. **The gate-runner binding and proof presence are optional when they should be required.**
   - `build/model-gate-run-summary.json` doesn't match the `build/model-clean-` prefix, so the `len(proofs)>prior` check at line 72 never applies to it.
   - `gate_runner_sha256` (line 84) is taken from current bytes and never compared with `summary['sources']`.
   - Bundle provenances, archive records and SPDX documents likewise aren't required to produce any proofs.
   - **Fix:**
     - Require `set(summary['sources'])=={'audit/model-gate-runner.py','audit/model-gate-commands.json','tools/audit_support.py','audit/python-lock.json'}`.
     - Require `summary['sources']['audit/model-gate-runner.py']==sha(runner)`.
     - Require `len(proofs)>prior` for every JSON file in `files`.

4. **Architecture is never bound to the archive pairs.**
   - Nothing checks `archive['architecture']` or `metadata['bundled_runtime']['architecture']` against `arch`.
   - `check_bundle` verifies the runtime for whatever architecture the manifest claims, not the one in the path name. An aarch64 bundle in the `x64` directories would pass every current check.
   - **Fix:** require both fields `==arch` for each of the four pairs.

## Correct as written
- **Assembler self-proof:** the assembler resolves its own path from `__file__`, so it still works after being copied unchanged to `audit/`. Run from the untracked `build/` copy, `git show` fails, which is the right outcome.
- **Source proofs:** these check current bytes against the recording commit (`CORE`), with HEAD clean and equal to `--commit`. This also covers the assembler's imports, because the model record's `sources` include every `tools/*.py`.
- **Gate rows:** the 16 rows are checked strictly (exact name set plus `len==16`, `returncode`, empty stderr, record path and hash, and stdout = record for JSON gates).
- **Dirty and qualification flags:** the dirty keys are walked through nested SPDX provenance, and `qualification` is checked.
- **Unit and negative-control counts:** 170 units with stdout/stderr hashes; model 4/16/5 with the exact 16-tuple set; SPDX 12 per document.
- **Pairing links:** zip → archive → bundle provenance and source provenance; SPDX → bundle tree; repeat zip/SPDX byte equality.
- **Bundled JAR is `PIN`, transitively:** `release_archive`/`spdx` call `check_bundle` → `check_artifact` against `audit/expected-build.json`, which pins `PIN`, and those sources are proven.
