## Blocker: the packaged-fixture tool can't run under `python -I -S`

- `tools/secure_release.py:4` adds its own directory to `sys.path`, and `:35` refuses to run without `-I -S`. `tools/check_secure_release.py` has neither.
- `check_secure_release.py:5` imports `audit_support`, `runtime`, `secure_build` and `historical_secure` by bare name. Under `-I`, Python leaves the script's directory off `sys.path`, so `python -I -S tools/check_secure_release.py` would fail with `ImportError`.
- That means the fresh packaged-fixture run at 6c5b3a5 must have been made without isolation. `PYTHONPATH`, user site-packages or the current directory could have supplied any of those modules or the standard library.
- `verify_python()` (`audit_support.py:55`) checks only the Python version and implementation, not the flags.
- So "QA invocation requires Python -I -S before output" is true for the packager. It is not true for the fixture QA, and the fixture record doesn't capture how Python was started.

There are two ways out:
- **Fix it:** copy the packager's `sys.path.insert` and flag check into `check_secure_release.py` before argument parsing or any output. Because of the `packager_commit==HEAD` rule (`:22`), that means repackaging and rerunning the fixtures at the new commit.
- **Disclose it:** leave the code alone and say in the ledger that the packaged-fixture runs were not interpreter-isolated.
