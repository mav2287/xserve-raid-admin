## Overclaims and gaps
1. **Broken links.** The report points to `audit/credential-persistence/observations.json` and says the reviews are archived under `credential-persistence/`. That directory doesn't exist. The only copy of the evidence is `build/credential-boundary-2/observations.json`, and `.gitignore` excludes all of `build/`. Fix: copy it into `audit/` and record its SHA-256 in the report, or reword both claims.
2. **Nothing is committed yet.** Both documents are untracked. Saying "clean fixture commit `27bb482`" is accurate for the run, but the record itself has no commit yet.
3. **"Native" vs "Rosetta" isn't recorded.** No host architecture, translation status or OS version is in `observations.json`. That claim rests only on the report's prose. Either label it as an operator statement or record those values in later runs.
4. **"Full packaged bytes/modes … checked" is weaker than it sounds.** `verify_packages()` compares each package against its own `provenance.json`, and that file isn't hash-pinned to `audit/secure-release/final-integrity.json`. Only the JAR, the dylib and the runtime tree are pinned independently. Either pin that file's hash in the script or soften the wording.
5. **The negative control covers less than "four behavioral negatives" suggests.** All four mutate only the original JAR and stop at the first case. They don't test the current-JAR path or the `keys`, management-absent and forget checks. That's fine as a sensitivity check for one assertion; say so.
6. **The scan only looks for direct field access.** It doesn't find calls to the management getters and setters in other classes. That's the stronger static support for the claim that the management password is only kept for the session. It also covers only the main JAR, not any other bundled JARs.
7. **An Apple-derived JAR copy sits in `build/`.** `negative-reference.jar` exists in both `credential-boundary-1` and `-2`. It's gitignored, but it should never go into `audit/`, a release ZIP or a handoff, because of redistribution rights.
8. **Minor wording points.**
   - "Original references occur only in RaidSystem" is also true of the current JAR; say both.
   - The 0600 file mode was checked only for files written by the current JAR. The original JAR's writer wasn't checked.
   - "Atomic" in `COMPLETION-STATUS.md` relies on earlier audit28 evidence, not this fixture.
