## Blockers

**1. The XML readback returns `Rate` as `Long`, but the fixture expects `Integer`, so every run fails.**
- `toPrefsContainer` stores `new Integer(getPollDelay())` (`credential-persistence-original.javap:2027-2032`).
- The original read path converts it with `checkcast java/lang/Long` (`credential-persistence-original.javap:2119`), and the project's own fixture comment says "plist integers are Long".
- So after readback, `validate(...)` fails at `"rate"` and `actual.equals(systems)` fails too (`CredentialPersistenceObservation.java:37,79`).
- Fix: give `validate` the expected Rate value: `Integer.valueOf(7)` for the in-memory container and `Long.valueOf(7)` for readback. Check the exact class, not just `Number`, so it matches the real reader. Compare `actual` to a copy of `first` with Rate set to `Long`, not to `systems`.

**2. The run needs both CPU architectures on one Mac.** The tool always runs both the aarch64 and x64 runtimes. On an Apple Silicon Mac the x64 runs need Rosetta 2, and an Intel Mac can't run the aarch64 runtime at all. Either confirm the host can run both, or add an `--architecture` option.
