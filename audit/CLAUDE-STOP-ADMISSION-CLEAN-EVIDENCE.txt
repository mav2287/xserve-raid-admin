## Weak spots in the assembler (the data checks out by reading, but the script doesn't enforce it)

1. **Pass/fail isn't checked for most gates.** For stop, admission, lock, connect, posting, shared, transport, resources, security and characterization, the script checks counts but never checks the outcome lines. I checked stop's 104 lines by eye; for the other gates I only searched for FAIL.
2. **Most stop vectors run on test JARs, not the shipped one.** 88 of the 104 run on modified test JARs (545fe4, 31f4cc, 86dff8, a123ed), which neither the ledger nor the script ties back to the candidate. The claim that the test hooks undo exactly comes from the stop tool's own `limits` text.
3. **The "16 active" label overstates.** The script's error message at `stop-admission-evidence-assembler.py:97` calls all 16 active vectors "candidate coverage". In fact only 8 run on the shipped JAR (202c9e); the other 8 run on the audit21 JAR (9f3f52). Both sets give identical PASS lines, so these vectors describe behaviour but don't show any difference between candidate and audit21.
4. **The audit21 JAR isn't hashed.** At `:88` the script reads `build/worker-exit-clean-3` without comparing it to 9f3f52. The matching bc6ff5 in the preserved audit21 SBOM makes up for this when reading, but the script doesn't check it.
5. **The runtime check uses an older build.** At `:53-59` it reads `build/logging-bundled-*`, not the audit22 bundles. It still holds because both contain the locked runtime, but it depends on an unarchived, ignored build directory.
6. **The unit-test result isn't tied to the run.** "136 passed" comes from a stderr file kept only as a hash, and the link to the sources rests on how the sources look now. `execution_worktree_dirty:false` is hard-coded.
7. **Smaller gaps:** the factory `jar_sha256` values aren't asserted. Only top-level `observations` arrays are counted, so about 40 transport and resources sub-observations (parser, header, io, policy and so on) aren't counted or checked. The ledger values `controller_contact`, `production_or_mounted_volume_tests` and `all_sources_clean` are written in as constants rather than measured; the ledger itself labels the first two as attestations.
