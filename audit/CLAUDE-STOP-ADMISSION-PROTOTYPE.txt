## False-positive risks in `StopAdmissionObservation`
5. **High: the sync guarded outcome has two possible causes.** A worker that dies with an unstarted transaction is reported as `CommShutdownException`. Nothing the test checks tells that apart from the guard working. `workerError` is always null because the wrapper catches the failure. Async is partly protected by the `callbackThread==worker` check; sync has no equivalent. To fix, assert:
   - the exception's top stack frame is `dispatchLoop`, created at 280;
   - SyncSender `claimed==true` and handled;
   - the hook ran exactly once.
6. **"Zero sends" comes from how the shadow is built, not from observation.** The memory `AcpxConnection` (`tests/java/ownershipfixture/AcpxConnection.java:35`) only records after `writeTo` returns. A `send` that was entered and then threw would also show zero. Add a counter at the start of `send`.
7. **One hook assertion can be swallowed.** In `read()`, the `check(!stopped,"Premature stop")` failure is never stored in `assertions`. If it fired on a second call, the worker containment would absorb it and the test could still pass. Record every hook assertion and count calls.
8. **`-Xcomp` doesn't prove compiled code ran.** If the JIT skips a method it can't compile (e.g. an unbalanced monitor), that method quietly runs in the interpreter. Capture `-XX:+PrintCompilation` and require `dispatchLoop` to be compiled with no `COMPILE SKIPPED`.
9. **`guarded_operations=0` is a fixed string** (`:45`), not a measurement. Remove it or measure it.

## Correctness gaps without vectors
10. **One sub-branch of 273 is never exercised.** With `connectionFailureSent=true`, 273 goes to 304 with no response, so no callback runs. For a claimed SyncSender, a dropped response would mean a caller that interrupt can't release.
    - It looks unreachable: the flag is set only in `doConnect`, alongside `retire`, and reset at 514. A handler failed there is already handled, so `claim` fails.
    - Prove that statically or add a vector.
11. **Missing vectors:**
    - a claimed sync caller that is interrupted before the guard stops it; it must get −102 and not hang;
    - two or more queued transactions, where every one must get −102 and nothing is sent;
    - an async after-admission control; all four controls are sync-only GetTime runs;
    - a stop while `claim` is blocked on the Sender monitor;
    - a mutating command.
12. **Structural checkers aren't updated.** `plan()` relies on the hash alone and never asserts the 234–241 / 273–304 code. Before promotion, update the `TAIL` expectation in `worker_exit_structure.py` and the reachable set in `assert_retry_unreachable`, as the earlier review said.
13. **The fixture isn't a real Manager.** It is built with `Unsafe.allocateInstance` and `prepare()` is called by hand, so constructor wiring isn't covered.

## Security
14. **Hook jars must stay out of the product.** Their Manager calls a fixture class placed in `com.apple.xsr.net`. `normalize()` would reject them by hash, but the product gate should also reject any constant that references `StopAdmissionObservation`. The hook jars should live somewhere other than next to candidate jars in `build/`.
15. **The scope label is still accurate.** No cancellation or receipt claim is made, and nothing limits the time spent after admission.
16. **The design doc is out of date.** `audit/STOP-ACTIVE-SEND-DESIGN.md:47-48` still says the async and pre-admission fixtures "remain required". It should be updated to record this prototype, its evidence and the open items above.
