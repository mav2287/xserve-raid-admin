## Concrete blockers
1. **No audit25 full-suite runner or evidence assembler.** The existing unit runners pin the full suite at 146 tests (e.g. `audit/connection-publication-unit-runner.py:20`). Adding `test_help_patch.py` (5) and `test_release_archive.py` (8) changes that count. A search for audit25 or help evidence assemblers only matches `baseline.py`. Nothing yet:
   - pins the new total,
   - runs the release-archive tests in a gate,
   - or ties `observations.json` and the 14 gate outputs to one clean commit.
2. **`release_archive.py` doesn't require clean source.**
   - Git state is read once, after verification (line 99). It isn't compared before and after, and a dirty tree isn't refused.
   - `check_bundle` (`verify_bundles.py:13-45`) never checks `source_dirty` in the source or bundle provenance.
   - So a development bundle gets a record that looks like a release one. It should require a clean initial state equal to the final state, and `source_dirty == false` in both provenance files.
3. **The release archive doesn't hash everything it runs.** `help_patch.py:3-4` imports `class_patch.py` and `sync_ownership_patch.py` at load time, via `baseline` and `verify_builds`. Neither file is in the hashed list at `release_archive.py:86`, so "binds all relevant source hashes" doesn't fully hold.
4. **Help scanner coverage is narrower than its error message suggests.** `check_help.py:42-48` only checks field and method references (tags 9/10/11) and exact class-name strings. It doesn't check:
   - class constants (tag 7), which cover `checkcast`, `instanceof`, `ldc` class literals and catch types,
   - field or method descriptors that mention `Ledu/stanford/ejalbert/BrowserLauncher;`.

   A reference of those kinds would get past the "Uncovered legacy browser reference" check. Expected set for tag 7: the two targets plus the self-entry.
