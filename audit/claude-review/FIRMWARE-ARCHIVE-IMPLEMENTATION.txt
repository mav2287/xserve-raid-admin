**Defects**
1. **The guard and probe classes can be replaced by classes in the jar** (`check_firmware_archives.py:79`). The classpath puts the jar first, then the compiled classes. If the jar contains `fixture/OfflineGuard` or `FirmwareArchiveProbe`, the JVM loads that copy instead. The probe checks where the wrapper came from, but not where it and the guard came from. Fix: put the compiled classes directory first (the wrapper check still catches a substituted wrapper), or also check the guard's and probe's load location.
2. **The wrapper comparison only goes one way** (`:57-58`). It only checks the class names that exist in the original jar. An extra `FirmwareBundleConnection*.class` in the candidate wouldn't be noticed. Fix: compare the full set of matching names in both jars, then the bytes.
3. **Nothing makes sure both architectures ran.** The script accepts a single `--runtime`, or the same runtime twice. That both pinned runs passed is your report; the tool doesn't enforce it. Fix: require exactly one runtime for each of `aarch64` and `x64`, with no repeats.
4. **One error path skips the fixed labels** (`:83`). `stdout.decode('ascii')` can raise an uncaught `UnicodeDecodeError`, and that message includes a raw byte value. Fix: catch it and raise a fixed label.
5. **Two lines claim more than they've checked:**
   - The `limits` text always says the x64 runtime ran under Rosetta, whatever the host was or which runtimes actually ran (`:91`).
   - The probe prints `guarded_operations=0` before `assertUntouched()` runs (`:72`). A guard failure still fails the run (non-zero exit plus stderr), so this only matters for how the output reads.
