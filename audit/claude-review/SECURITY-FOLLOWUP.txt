## Defects
1. **Java 8 `javap` doesn't print the superclass or interfaces** (`check_security.py:23`). The `this_class`, `super_class` and `interfaces` lines only appear in `javap` from JDK 11 on. With the locked Java 8 JDK, the identity check only compares the version and flags lines. In Java 8 the hierarchy only appears on the class declaration line before `minor version`, and that line is never compared. So the independent check doesn't cover the superclass or interfaces of any of the three targets. `SecurityProbe` checks the superclass at runtime, but only for `Handler`. Fix: include that declaration line in the comparison.
2. **The override inventory can miss overrides** (`check_security.py:43`). The pattern only matches exactly `public java.lang.String toString();`, so a `public final` or `public synchronized` override would be missed. Fix: match `^  (?:\w+ )*java\.lang\.String toString\(\);$`.
3. **The override inventory only scans `com/apple/` and `com/chaotic/`** (`:34`). A request subclass in any other package is missed. So is a subclass whose chain to `RequestMessage` runs through a class outside those two packages. Fix: scan every class in the JAR.
4. **Minor gaps in the independent check:**
   - The target filter (`:22`) drops every method with the target's name, whatever its signature. Overloads therefore go unchecked, and so do the target's non-Code attributes, such as `Exceptions`.
   - The opcode check (`:69-74`) runs `javap` without `-v`. Max stack, max locals, an empty exception table and the `resolve` method signature are never checked independently.
   - The golden hashes cover all of this today.
