1. **Match on the level's integer value, not object identity.** In log4j 1.2, the deprecated `Priority.ERROR` and `Priority.FATAL` are separate `Level` objects from `Level.ERROR` and `Level.FATAL`. A caller using `log(Priority.ERROR, …)` would fail your `==` check and be silently dropped. That fails closed, so it isn't a safety problem, but it is a coverage gap. Compare `event.getLevel().toInt()` against `Priority.ERROR_INT` and `FATAL_INT` instead, or record the gap in writing. Your `RuntimeException` catch already covers a `ClassCastException` from `getLevel()`.

3. **The once-per-process flags need to be static, or you need to show configuration runs only once.** With instance fields, any reconfiguration creates a new appender and resets the flags. The scan showing no configuration calls supports the claim, but say that's where the guarantee comes from.

4. **Disclose that a blocked write holds locks.** `Category.callAppenders` synchronizes on every category from the logger up to and including root, and your `doAppend` is synchronized too. While a write to stderr is blocked, every thread logging at ERROR or FATAL also blocks, not just the one writing. DEBUG and INFO calls are unaffected because they're filtered out before `callAppenders`. The writes are capped at two, so this is a disclosure item, not a design change. Also note that `System.err` is whatever the app has set at write time. If the app ever calls `System.setErr`, output goes there; setting the flag before printing already prevents recursion.
