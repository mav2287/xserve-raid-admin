## Gaps worth closing (not blockers)

1. **`assert_worker_failure_stop` doesn't check `retire`'s exception table** (`check_security.py:57`).
   - A row like `0 4 8 Class java/lang/Throwable` would send a failed stop to the existing `return` at 8. That passes the verifier and leaves the instructions unchanged, so the callback would run without a stop.
   - `report` and `shutdownRequired` already check their exception tables, so `retire` should too.
   - Today's risk is low, because the source-to-jar byte match pins the actual bytes. Add the check and a test case to `test_worker_stop_gate.py`.
2. **The exact-class check relies on an unrecorded fact.** `manager.getClass()!=CommunicationsManager.class` turns any subclass into a guaranteed worker death.
   - In that case there is no callback, synchronous waiters hang, and on the prefix path the connection isn't closed (`retire` stops before closing).
   - Record a scan of all 2844 classes showing that nothing extends `CommunicationsManager`.
   - Also write the failed-stop outcome down as an accepted residual: worker dies, no exit cleanup, waiters stranded. There is no runtime test of that path; only the static bytecode check covers it.
3. **The rerouted handler field has no unit test.** It is enforced at `class_patch.py:374`, but no test in `test_class_patch.py` flips the bytes of the 462 handler target.
4. **check_architectures' first-line comparison can pass vacuously** (`:168`).
   - If `a[0]` lacks `connected=true`, `.replace` changes nothing and the check becomes a plain equality.
   - Assert that the token appears exactly once.

   - The run description at `check_security.py:287` says "original handler metadata retained", but 307→462 changed.

   - `assert_session_containment` and `test_session_stop_gate.py` no longer check the real build. Either retire them or label them historical.

   - Bytecode mutants 307→307 and 573→344: these are covered by the source mutants plus the original-mode differential. The combined commit should state that.
   - The `RaidSystemAgent` "Terminating Updates" test: still unmeasured, so make no claim about it.
